# Requirements reconciled across the two supplied packs

The master architecture supplies the `/v1` contract, purpose-aware workflow and 5,000-record synthetic oncology scenario. The main hackathon kit supplies the original prototype, 480-record regression fixture, 26-family register and more specific frontend/evaluation/export acceptance requirements. Both are preserved for reference; their claims are not substituted for current execution results.

## Working integration

- The original kit was executed separately: 61 tests pass in the installed environment. Its declared historical dependency ranges differ from the current locked environment; see [KIT_BASELINE.md](KIT_BASELINE.md).
- The current engine/API reproduces the kit's 75/480 public-rule verified unique correct matches and 20/480 after ZIP removal. The selected protected scientific answers are identical across those candidates. Fixture bytes and Apache attribution are retained.
- The current API keeps the master architecture's data/recipe/finding separation. `/v1/demo` selects the 5,000-row architecture fixture; `/v1/demo?fixture=kit` selects the original benchmark. An original `/api` client must migrate to the [frozen current contract](../IMPLEMENTATION_CONTRACT.md); the two endpoint namespaces are not interchangeable.
- Exact-linkage matching receives public transformed known values, not the private correspondence used afterward for scoring. Unknown external methods, missing correspondence, unknown membership and unsupported known-field mechanisms abstain. Finite-table enumeration does not receive an invented confidence interval.
- The register distinguishes 26 threat families from engine-specific analyses, and preserves 17 protection entries with actual coverage. pyCANON is installed and runtime cross-checked; other optional bridges remain unavailable.
- Interval-straddling filters abstain. Common-domain comparisons distinguish coarse-domain preservation from literal encoding changes. Subgroup retention, missingness and scientific distortion remain separate. See [KIT_EVALUATION.md](KIT_EVALUATION.md) for calculated counterexamples and units.
- Candidates freeze the recipe, original schema, threat context, workload and actual output. CSV export requires authority, limitations and reviewed-candidate acknowledgments, and blocks retained direct identifiers. Owner audit downloads carry a confidentiality warning and exclude raw previews/lineage/secrets.
- The process binds loopback, rejects foreign origins/hostnames, bounds chunked bodies before parsing and keeps multipart uploads in RAM within the size limit. Session clearing releases application references, not OS-level secure erasure or deletion of downloaded files.

## Product and acceptance boundaries

The user's latest visual direction overrides the older kit mockup: a compact persistent workspace inspired by Docs/Spotify, with a library, central canvas and contextual inspector. Current frontend review evidence belongs in `frontend/DESIGN_AUDIT.md`; final live-browser results and screenshots belong in `artifacts/DELIVERY_STATUS.json`. These files must report actual execution and limitations, not infer success from source or test counts.

The hackathon scope implements row-release preparation/audit. It does not promise all possible attacks, legal authorization, a universal safety score or immunity at maximum strength. Independent population inference, sophisticated approximate auxiliary linkage, longitudinal/genomic analysis, ARX/R bridges, production synthetic evaluation and durable DP aggregate release accounting remain explicitly unimplemented. The kit's aggregate Challenge10 lane is a separate optional architecture and is not claimed complete by this microdata workbench.

No report or Pareto status clears a dataset for publication. A failed or unassessed condition remains visible; the measured candidate set can legitimately contain no configuration meeting the requested constraints.
