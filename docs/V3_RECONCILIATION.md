# PRISM v3 reconciliation and product decisions

The supplied v3 Markdown and ZIP contain the same specification. Their complete contents and import hashes are retained under [spec/v3](spec/v3/README.md). These are proposed engineering designs, not evidence that the application ran. The pack's25 arithmetic/catalog checks are separate from application tests.

The user clarified the actual launch product: a desktop-style proof of concept hosted so judges can try it with their own files. The former fictional-only upload restriction was a product mistake and has been removed from the current hosted adapter. The app has no account, sign-in or permission checklist in the ordinary import-to-export workflow.

## Changes adopted

| Useful v3 idea or concrete review finding | Implemented result |
| --- | --- |
| Show the source immediately on first use | Compact hosting summary, removal of the duplicate review introduction, concise empty ledger and no inactive preference panel before a real candidate exists. Import table and Semantic example are visible actions. |
| Real Protect and Compare paths | CSV, JSON and XLSX import on the hosted Archie app, plus external protected-file comparison with explicit mapping and pairing. The same authoritative Python engine processes examples and uploaded files. |
| Persistence must support actual work | Archie Core stores visitor-owned uploaded bytes in separate records and compact session configuration. Cold invocations reconstruct the actual source/protected tables. Clear session deletes its uploaded records. |
| A centered interval is reversible | A25th deterministic category scans explicit `CI[lower,upper]` output encodings and reports readable integer midpoints. Ordinary shared bins are a negative control. External output does not prove the midpoint was its unknown original value. The manual option is explicitly an unsafe demonstration, not privacy protection. |
| Jev input must be inspectable and bounded | View model input shows the actual schema metadata. Interpret runs directly on explicit action; no forced approval dialog. At most eight ambiguous fields and twelve neighboring labels are included. An internal input digest rejects stale metadata before a provider request. No record cells are sent. |
| Do not let old responses replace current work | Uploads use the workspace single-flight, abort and epoch guards. Closing the import dialog cancels the pending request. Import and audit entry points disable during active operations. |
| Preserve actual frozen recipe identity | A reproduced24-candidate cold-replay mismatch was fixed by hashing the restored frozen recipe, including its original version. External audits replay their actual protected table rather than pretending it was produced by a local recipe. |
| Keep export understandable | Protected CSV is a direct download from the current candidate. Removed the three acknowledgment-checkbox ceremony without fabricating user declarations. Current-evidence and recognized identifier checks explain any concrete blocked result. |

## Working foundations retained

The six connected views, original/protected comparison, human field-role and row-grain review, independent identifier scans,145-type/13-family ontology, typed Jev adapter, exact field corrections, immediate draft preview, frozen findings, selected-query utility, bounded real recipe search and explicit unsupported coverage remain. The existing ontology was not replaced just to match v3's144/15 catalog counts. The semantic registry now has25 actual categories; the original26-family threat catalog is separate. A listed category is not a claim that its specialized attack ran.

The user reviews field meanings because those choices define what the tool measures and transforms. This is part of the analysis, not a legal approval or account permission. The global preference selects actual evaluated candidates; it never generates a universal safety percentage or calls Jev during movement.

## Deliberate boundaries

V3 proposes a broader60-rule DSL, relation graph, distinct-subject observer model,180-case model benchmark,90 acceptance cases, standalone release-only inspection, specialized population/synthetic attacks and optional library adapters. Those are not declared complete merely because they appear in the supplied report. Unsupported methods remain visible as unassessed. Current import formats are CSV, JSON record arrays and single-visible-sheet XLSX, not Parquet/TSV. JSON null and empty strings are not given the richer missing-reason ontology proposed in v3.

This build is a hosted demonstration of the desktop workflow, not a Windows executable release. The local wheel and source launcher provide the local engine. The platform imposes a3MiB hosted file limit; local intake supports50MB. There is no automatic project restore after an Archie page reload. Downloads preserve the artifacts the user chooses to keep.

Whole serialized-artifact re-import assessment, arbitrary companion-file review, cross-release accounting and pinned historical engine binaries remain future work. Candidate inputs and meanings are frozen; serverless replay executes the current deployed engine. No population identity probability, formal differential privacy, universal scientific validity or legal clearance is inferred from a completed scan.

The independent source review found and repaired actual workflow problems, rather than certifying catalog counts.
